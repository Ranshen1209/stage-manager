# Stage Manager for Windows · 台前调度 0.3.10

Windows 10 / 11 原生桌面应用，使用 .NET Framework 4.8、WPF 和 Win32 / DWM。不联网，无遥测。Windows 11 自带 .NET Framework 4.8 或更高版本；较早的 Windows 10 可能需要先安装。

## 使用

双击 **bin\StageManager.exe**，或从 [Releases](https://github.com/Ranshen1209/stage-manager/releases/latest) 下载 ZIP，解压后运行 EXE。正常版标题为“Stage Manager · 台前调度”，首次启动保持暂停，后续启动沿用上次运行或暂停状态。列表显示当前虚拟桌面、所选显示器上的应用窗口，包含最小化窗口。

1. 检查“所有窗口”的识别结果，按标题 / 应用名搜索，或选择显示器范围。
2. 点击“开启台前调度”。点击窗口组切换，同一显示器的其他组自动最小化，其他屏幕保持原状；暂停时恢复接管前的布局。
3. 点击“＋ 分组”选择相关窗口，也可以拖动卡片到另一组，或拖到桌面上正在显示的受管理窗口。
4. 多窗口组下面显示各成员。点击成员会将对应窗口显示在同组其他窗口上方，也可聚焦成员后按 Enter / 空格。拖动成员到另一条成员的上半部或下半部，可调整顺序；跨组放到成员处可插入到该位置。拖到侧栏空白处 / “移出分组”目标即可拆出。拖动过程中可按 Esc 取消。
5. 实际应用窗口也可以通过拖动标题栏放入侧栏的分组。目标不在当前视野时，保持按住鼠标并靠近列表上 / 下边缘即可平滑滚动，越靠近边缘越快；继续移到侧栏底部也能向下滚动。移回目标卡片后停止滚动，松手加入；Esc 取消。卡片和组内成员同样支持。此操作只在侧栏可见且调度开启时生效；调整窗口大小不会触发分组。
6. 拖动侧栏边框调整大小，拖动标题栏调整位置。侧栏最小宽度为 180 个逻辑像素（100% 缩放时 180 像素，150% 时 270 像素），卡片随宽度收缩，窄侧栏的文字会省略或换行。总览和侧栏的位置、大小分别保存，切换界面或重启后恢复；重启沿用上次的侧栏 / 总览模式，并保留总览的最大化状态。收起到屏幕外侧时保存侧栏展开的位置。
7. 侧栏靠近屏幕左右外边缘时可以吸附。其他窗口覆盖其范围后会平滑收起，鼠标在屏幕边缘短暂停留可唤出。开始拖动受管理窗口时，隐藏的侧栏也会平滑滑入；正在收起时从当前位置折返。多显示器内部接缝不作为隐藏位置。操作侧栏或菜单时保持展开。开启“减少动画”或关闭 Windows 动画效果后直接展开。

拖动时，鼠标旁会出现带应用图标、名称和目标说明的莫奈圆角浮层，随鼠标移动；开始拖动时轻微抬起，开启“减少动画”后直接显示。成员行和分组卡片边缘以插入线指示排序位置，松手后一次提交；取消不改变原顺序。排序只调整显示顺序，不切换、最小化或移动实际窗口，顺序会保存并在重启后恢复。拖动整个分组的标题或卡片，到其他卡片上 / 下边缘排序；多列时也支持左 / 右边缘及卡片之间的空隙。放在卡片中间仍然是合并分组。上述操作同时适用于总览和侧栏。

相邻成员之间只有一个插入位置：上一行下半部、两行间隙和下一行上半部显示同一条提示线。提示线居中放在间隙中，与卡片边框留出距离；多列时在列间显示竖线，换行和列表首尾显示横线，并避开较高的相邻卡片。

侧栏始终显示当前桌面与显示器范围内的全部窗口，不继承总览的搜索文字或“我的分组”筛选。拆组后立即显示两个独立窗口，无需切换页面；返回总览时保留原来的筛选选择。

拖动时，侧栏旁显示统一的圆角浮动面板，包含窗口数量、当前目标组名称、“加入当前组”和“移出分组”两个操作。目标使用莫奈底色与勾选标记高亮，长组名省略显示，面板自动选择屏幕有空间的一侧。侧栏从屏幕外滑入时，面板等待展开完成再淡入，避免停留在移动前的位置；提前结束或取消拖动不会延后弹出。明暗模式和莫奈配色同步生效；开启“减少动画”时取消弹出淡入。

侧栏拉宽至约 461 个逻辑像素时自动排列为 2 列，677 时为 3 列，更宽时继续增加列数；预览按卡片宽度调整比例，卡片沿各行顶部对齐。列数计算预留固定滚动条空间，避免滚动条出现后反复换列。高分屏按逻辑宽度计算，同样的窗口尺寸保持相同列数。

侧栏禁止最大化，包括标题栏双击和系统最大化命令。仍可拖动边框调整宽高、使用多列布局。需要最大化查看时，点击“展开总览”，总览继续支持最大化。旧版留下的、同时铺满工作区宽高的侧栏尺寸会恢复为可用的侧栏尺寸；普通手动设置的宽侧栏不会被缩回单列。

侧栏底部不显示黄色通知卡片，导航栏底部的品牌 / 版本文字也已移除。设置页不显示白名单规则数量、手势和快捷键的日常黄色状态文字；需要处理的错误和冲突以普通说明文字显示。

## 应用白名单

在 **“设置 → 应用白名单”** 中管理。初始规则列表为空，不会替你加入任何应用；添加后立即生效。白名单开关可以临时暂停所有规则，列表和开关都会保存。
每条规则旁的“重命名”支持直接修改显示名称，点击“保存”或按 Enter 提交，点击“取消”或按 Esc 放弃。名称会保留到下次启动，不影响原有 EXE 路径或应用身份匹配；重新添加同一应用也会保留已修改的名称。名称最长 160 个字符，不能为空。

鼠标悬停在白名单区域时，列表有更多内容就滚动列表；列表不需要滚动，或已经到达当前方向的顶部 / 底部时，滚轮会继续滚动外层设置页。重命名输入框上方也遵循相同行为。

- **从已打开的窗口添加**：支持搜索和多选当前 Windows 桌面的窗口，添加的是这些窗口所属的应用，新开的同应用窗口也会放行。右键窗口卡片或组内成员也可添加；多窗口组的卡片针对当前预览应用，组内成员针对该成员。
- **选择 EXE 文件**：支持多选，按完整路径匹配，不按同名文件泛匹配，不会运行选中的程序。应用更新后如果 EXE 路径变化，需要移除旧路径再添加新路径。
- **移除**：设置列表中的“移除”删除对应规则；右键卡片“将此应用移出白名单”会移除所有匹配该应用的规则。

从窗口添加时优先使用 Windows 提供的具体应用身份，避免把共用浏览器进程的其他网页应用一起放行。读取不到应用身份时使用 EXE 完整路径。手动选择浏览器 EXE 则会放行使用该路径的全部窗口。没有可用身份或路径的窗口，可通过选择 EXE 添加。

白名单应用不加入托管分组，不会因为出现或获得前台焦点而收起当前工作组；切组、平铺、暂停和退出也不主动调整它们的窗口。白名单窗口仍显示在“所有窗口”及侧栏中，标记为“白名单”；点击只打开该窗口，不启用暂停中的调度，也不切换当前组。“我的分组”只列出托管分组。

正在管理的窗口加入白名单时，会从原组移出，原组其他成员与自定义名称保留。加入时保留当前位置和最小化状态，已收起的窗口不会自动弹出，可从任务栏或白名单卡片打开。移除规则或关闭白名单开关后，窗口以当前状态重新接管，按普通应用规则归组；不会自动重建它之前所属的手动混合分组。

规则适用于所有显示器及 Windows 虚拟桌面，但不会把白名单窗口搬到其他桌面或显示器。真正关闭或隐藏到托盘的应用不会被重新启动、恢复出来；全屏避让仍按原有设置工作。演示模式使用独立的白名单设置，仅管理演示窗口。

默认按应用自动归组：同一应用的多个窗口属于同一组；运行中再打开该应用的窗口时，自动加入已有组，保留原窗口的位置和显示状态。新窗口在前台时跟随到它所属的组，并保留新窗口的焦点。仅在后台发现的新窗口不会主动切走当前组。

自动归组优先使用 Windows 提供的应用身份，普通桌面程序使用完整可执行文件路径，因此同应用的不同进程也可归组；有独立身份的浏览器安装应用分别识别。无法可靠识别的共享宿主窗口保持独立。手动创建的混合分组和拆分仍保留；同应用已有多个手动分组时，新窗口优先加入该屏幕当前活动的匹配组，否则加入列表中第一个匹配组。此规则只接纳新发现的窗口，不会重新合并已经手动拆开的窗口，也不跨显示器或虚拟桌面归组。

从 Windows 任务栏或 Alt+Tab 选择组内成员时，会保留所选窗口的前台层级和键盘焦点；普通窗口与最大化窗口均适用。从侧栏或快捷键重新进入分组时，优先回到该组上次使用的成员。前台事件触发及时跟随，定期扫描继续补充窗口发现。

分组预览和应用图标跟随最近使用的成员，包括在同一组内通过任务栏最小化、恢复或切换窗口；组名和成员顺序保持不变。该成员已最小化时优先预览仍显示的成员，整组收起时保留最近使用的成员。恢复过渡会核验实际窗口层级，处理异步恢复稍晚改变前后顺序的情况，避免只保住键盘焦点却让所选窗口被同组成员遮挡。

切换采用分阶段恢复：先恢复目标组，待窗口状态稳定后再收起旧组，减少异步操作间的空白过渡。变化中的实时预览暂时显示原有主题卡片，再平滑回到正常预览；背景透明度、模糊和文字不透明度保持各自设置。其他应用自身的 GPU 重绘或渲染器产生的白帧仍受该应用及显卡环境影响。

## 多显示器与 Windows 虚拟桌面

远程软件开启虚拟屏、关闭物理屏，断开后恢复物理屏，或运行中更改分辨率 / 缩放时，调度会等待屏幕配置、窗口归属、实际窗口位置、正常窗口尺寸和 DPI 至少连续稳定 1.5 秒。主窗口 / 侧栏的 DPI 布局也参与判断。暂时隐藏或未识别到的已管理窗口有最长 15 秒的等待期；如果尺寸仍然持续变化，则继续等待，不因超过 15 秒就恢复调度。期间冻结日常布局写入、分组和窗口自动操作。整组成员最终位于同一屏幕时，会整体迁移并保留组名、成员顺序和最近使用的成员。虚拟屏先开启而物理屏延后关闭时，暂时离开所选屏幕的分组会保留，回到管理范围后继续使用。

屏幕稳定后，受管理的应用窗口会按旧、新可用工作区的比例同步调整大小和位置。宽高使用同一个缩放倍率：取工作区宽度比和高度比中较小者；长宽比不同则将整套布局居中放置，保留空余边带，不分别拉伸窗口的宽和高。例如可用工作区从 3840 × 2160 变成 1920 × 1080 时，窗口宽高、位置偏移和窗口间距一起减半。计算使用扣除任务栏后的实际工作区，不再额外叠乘 DPI 倍率；仅改变 DPI、工作区物理尺寸相同时，保持窗口占屏比例。

当前显示的组会主动应用一次计算结果；收起的组保持最小化，切回该组时再应用，之后普通切组只恢复显示状态。保留当前最大化 / 最小化状态；未变化屏幕上的窗口保持原布局。应用拒绝自动位置请求时，不在每次后台扫描中反复重试。白名单窗口不参与自动等比调整，已关闭的窗口不会重新打开。

每个窗口的布局基准与已经缩放后的结果分别保存。连续切屏时始终从未缩放的基准计算，避免尺寸、位置和取整误差不断累积；重启本应用后也保留这个基准。手动移动或调整窗口大小后，以新布局为基准。切屏期间主动拖动窗口时，以用户操作为准，不再把这个窗口拉回自动计算的位置。目标应用可能强制最小窗口尺寸；接受这一限制后的实际尺寸不会立即替代原基准，从而避免切回大屏时再次错误放大。

重启后恢复布局、暂停 / 退出恢复原布局等操作同样使用工作区比例换算，区分窗口工作区坐标和屏幕坐标，限制原本越界或过大的窗口。无需维护固定分辨率的物理屏 / 虚拟屏档案。旧版没有坐标空间信息的应用窗口记录先沿用实际位置；新捕获的有效位置会建立布局基准。

切换过程中暂停或退出时，仅恢复原显示状态，不提交未稳定屏幕上的旧坐标。切换过程中请求开启调度会等待稳定后执行；暂停可取消这一等待。恢复几何位置时每次选择一种原生操作，取消连续发送两次位置命令的旧路径。

主窗口与侧栏在切屏期间停止吸附动画和位置保存，等待 WPF 应用新的 DPI 后使用当前窗口范围；只有超出工作区时作一次边界调整。贴边隐藏的侧栏使用展开位置换算回可见区域。重启本应用时，已移除屏幕上的已保存分组仍按严格的窗口身份匹配到当前屏幕；跨 Windows 桌面移动或真正关闭的窗口不会被拉回、重开。正常拖动单个成员到另一块仍在使用的屏幕，继续按独立屏幕规则拆分；最终散落在不同屏幕上的成员也保持屏幕隔离。

这些处理针对受管理应用窗口的等比布局、旧坐标回写、重复移动和过早恢复。窗口自己的最小尺寸、最大化状态或应用主动重设位置可能限制最终结果；本版未进行真实窗口、DPI 切换或远程连接验证。

主窗口、侧栏、弹窗与菜单跟随所在显示器的 Windows 缩放比例。发布程序显式启用 .NET Framework 4.8 的 WPF 每屏 DPI 渲染；跨屏变化由 WPF 先完成缩放，再更新侧栏停靠位置、材质和预览。窗口位置记录同时保存 DPI 与工作区，重新打开时保留逻辑尺寸和距离屏幕边缘的间距，避免一直沿用低分屏的像素大小。旧版没有 DPI 的位置记录按 100% 基准迁移一次；托盘菜单根据鼠标所在屏幕定位，不使用主窗口所在屏幕的缩放比例。

支持“全部显示器”或单独选择一块显示器。全部显示器模式下，每块屏幕独立保留自己的活动分组；分组切换、快捷键循环和平铺只影响相应屏幕，全屏避让也按屏幕处理。创建分组和拖放合并限于同一屏幕；先把实际应用窗口移动到目标屏幕后再分组。组内成员单独跨屏移动时，会从原分组拆出。显示器拔插或布局变化后，自动更新显示器范围和侧栏位置，继续运行；不同缩放比例沿用 PerMonitorV2 DPI 支持。

列表只显示当前 Windows 虚拟桌面的窗口，切换桌面时分别保留各桌面的分组和活动状态。设置中的“侧栏跟随 Windows 虚拟桌面”默认开启；只移动 Stage Manager 自己的窗口，不把其他应用跨桌面搬动。关闭后侧栏留在原桌面；通过托盘主动打开时仍在当前桌面显示。桌面归属和本应用窗口移动使用 Windows 10/11 公开接口；当前桌面 ID 只读获取 Explorer 的状态，以兼容空桌面和固定到所有桌面的应用，不使用 Explorer 的私有 COM 接口。

退出或暂停不会强行切换虚拟桌面。当前桌面先恢复；其他桌面的恢复记录保留在本地。暂停后保持程序运行，切回对应桌面时自动继续恢复；如果已完全退出，则下次运行后继续处理。用户已经关闭、隐藏到托盘或主动移到另一虚拟桌面的窗口会跳过。真正最小化的窗口仍按原始状态恢复。

## 主题、透明度和模糊

“设置 → 外观与材质”提供浅色、深色、跟随系统。全界面采用莫奈色系：奶油白、鼠尾草绿、雾蓝、淡紫；深色模式采用对应的低饱和配色。系统应用主题变化时会自动同步，托盘菜单、弹窗、演示内容和示例窗口标题栏使用同一套主题。

“莫奈配色”可选择 **睡莲、吉维尼花园、塞纳河晨雾、紫藤花影、日出印象、玫瑰暮色** 六套配色，每套均有浅色和深色版本。选择即时生效并保存；“跟随系统”只切换明暗，不改变所选配色。每套配色包含背景、控件、文字、提示和演示内容的完整色板。

主窗口与侧栏有独立的**背景不透明度**（45–100%）及**背景模糊模式**。滑块只调整背景、卡片和输入区域的材质颜色层，文字、图标、控件前景与窗口预览始终保持原有不透明度。开启模糊时，Windows 先模糊背景，再合成界面；关闭模糊时背景可清晰透出，文字同样不会变淡。修改侧栏材质后切为侧栏可查看效果。

模糊提供关闭、柔和、亚克力三种模式。Windows 11 使用系统背景模糊，柔和模式的色彩覆盖更轻，亚克力模式更浓；模糊半径由系统控制。旧版系统使用兼容材质，不支持时回退实色背景并提示。Windows 透明效果策略、远程桌面和显卡环境可能影响材质。

主窗口和侧栏失去焦点后继续保留所选的模糊外观；只保持背景绘制状态，键盘焦点仍随用户选择的应用切换。材质切换会在透明合成更新后重新应用，避免关闭模糊再打开时残留上一种材质。

主窗口、侧栏和自定义弹窗由 Windows 11 统一绘制圆角，界面背景铺满窗口，移除重复裁切、叠加亮边及右下角的旧式缩放标记。仍可拖动窗口边缘调整大小。旧版系统使用单层原生区域裁切；最大化时使用直角，恢复后恢复圆角。

图标的唯一绘图源为 **assets\stage.svg**。保留重叠窗口轮廓，使用奶油白底、鼠尾草绿主窗口、淡紫后窗。任务栏、主界面、弹窗、演示及托盘使用同一窗口符号与莫奈配色系列；托盘版使用细线框和透明内孔，并加深绿、紫两色，提高小尺寸辨识度。托盘变体也定义在同一个 SVG 源文件内。

窗口卡片优先显示应用图标，仅在图标不可用时显示首字母占位，避免字母从透明图标下方露出。点击和悬停不再降低整张卡片的不透明度，图标、文字与原生预览保持一致的亮度。

## 后台和开机启动

- “关闭窗口后继续在托盘运行”默认开启。关闭按钮 / Alt+F4 隐藏界面，调度继续运行；托盘右键“退出并恢复窗口”才会结束程序。
- 关闭上述选项后，关闭窗口会恢复布局并退出。
- 开机自启默认关闭，需要在设置中主动开启。
- 自启可选择“静默驻留托盘”或“显示上次的窗口界面”。启动时沿用上次的运行 / 暂停状态；静默启动不弹出主窗口或侧栏。
- 双击托盘图标或再次运行 EXE，可唤出后台界面。Windows 注销时尝试恢复布局并退出。
- 自启仅写入当前用户的 Run 注册表项，不需要管理员权限。便携版移动位置后，应在新位置重新开关一次自启。

## 自定义快捷键

在“设置 → 快捷键”中点击现有组合，随后直接按下键盘组合，例如 **Ctrl + Alt + K**，松开按键后自动检查并保存。支持左右两侧的 Ctrl、Alt、Shift、Win 和常用主键。按 Esc、再次点击录入按钮或切换到其他窗口可取消；无修饰键的 Tab 退出录入并继续键盘导航。点击“清除”取消该项绑定，“恢复默认快捷键”重置全部绑定。冲突时原有绑定保持有效。

只在主动录入期间临时捕获按键，避免录入组合同时触发其他操作；完成、取消或超时后停止捕获。修改键单独按下不会保存；录入最长持续 30 秒。演示模式同样支持按键录入。

| 默认组合 | 操作 |
| --- | --- |
| Ctrl + Alt + Space | 开启 / 暂停并恢复 |
| Ctrl + Alt + Right | 下一组 |
| Ctrl + Alt + Left | 上一组 |
| Ctrl + Alt + Backspace | 紧急恢复布局 |

检查包括本应用重复绑定、已知系统保留组合和其他程序通过 Windows 注册的全局快捷键。无法枚举各应用内部的局部快捷键。演示版可编辑和检测，但不会长期占用全局快捷键。

## 中键切换 Windows 桌面

在 **“设置 → 鼠标手势”** 中开启“按住中键左右移动，切换 Windows 桌面”。此开关**默认关闭**，从旧版升级也不会自动开启；关闭时没有鼠标监听线程，也不拦截中键。开关、方向和距离会随设置保存。

1. 先按 `Win + Tab` 创建至少两个 Windows 虚拟桌面。
2. 按住鼠标中键，向左移动切换上一个桌面，向右移动切换下一个桌面。
3. 每次按住最多切换一次，松开后再次按住才能继续。首尾桌面不会循环，也不会自动新建桌面。

“反转左右方向”可调整为自己习惯的方向。触发距离默认 100 个逻辑像素，可调范围为 40–240；数值越大，需要移动越远。按下时按鼠标所在显示器的 DPI 换算，兼容高分屏和负坐标屏幕。切换使用 Windows 的 `Ctrl + Win + Left / Right`，由系统提供桌面切换动画；切换的是 Windows 桌面，Windows 会同时切换所有显示器的桌面，与每屏独立切换窗口组不同。

开启后，中键拖动用于桌面切换，浏览器自动滚动、绘图软件中键平移等原生按住行为会受影响。普通中键点击在松开时补发；小范围抖动可容忍，已发生拖动或取消的操作不会补发点击。纵向拖动、滚轮或其他鼠标键活动会取消本次识别；检测到修饰键或 Esc 按住时也会取消。全屏应用、按住修饰键或其他鼠标键的操作，以及权限高于本应用或无法确认权限的目标窗口，均跳过手势，保留原有中键输入。

手势独立于窗口调度，调度暂停或应用隐藏到托盘时仍生效；关闭手势开关或完全退出应用后停止。隔离演示只显示和保存演示设置，不安装鼠标监听、不切换实际桌面。手势不需要重启或管理员权限。远程软件若把中键事件传入当前 Windows 会话，可以参与识别；如果在客户端截获中键或系统快捷键，则需按远程软件自身设置处理。本版尚未进行真实远程手势测试。

## 保存和恢复

设置位于 %LOCALAPPDATA%\StageManager\preferences.json；总览与侧栏位置、启动界面模式、最大化状态、主题、材质、快捷键、中键手势、后台及自启显示方式会持久保存。演示设置使用独立的 demo-preferences.json。

分组会话单独保存到 layout.json，包含手动分组名称、成员顺序、每块显示器的活动组、最近使用的成员及各窗口在调度中的位置。完全退出会先记住会话，再恢复接管前布局；重新打开 Stage Manager 时恢复仍然打开的窗口及分组。暂停后重新运行仍保持暂停，手动开启时再恢复分组。当前实际前台选择优先于记忆中的活动组，避免启动时遮住正在使用的窗口。

恢复会核对窗口句柄、进程及其启动时间、窗口类、显示器和虚拟桌面归属。已关闭、隐藏或换了身份的窗口不会重开，也不会按相同标题误配；其他虚拟桌面的分组等待切回对应桌面再恢复。此功能用于重启 Stage Manager，不会在重启 Windows 或其他应用后自动重新打开程序。旧版未保存过的分组无法追溯，新版运行后开始记录。分组文件采用原子替换，与恢复日志独立；读取损坏时保留备份，保存失败时显示提示，原始窗口恢复仍可工作。

修改应用窗口前，先原子写入 recovery.json；退出后恢复原来的位置、尺寸和最小化 / 最大化状态。异常退出后，下次启动会尝试恢复。恢复失败时保留记录，设置文件损坏时保留原文件备份。组内成员关联的是当前运行中的窗口，本次运行的分组不会自动复活已关闭的应用。

某个窗口恢复失败后，调度保持暂停，该记录等待“设置 → 恢复窗口布局”手动重试；后台扫描继续识别窗口，但不会每秒重新恢复同一失败窗口、反复报错或清空实时预览。其他虚拟桌面的记录仍在切回对应桌面时处理；一个窗口失败不会阻塞其余窗口。已经关闭或隐藏到托盘的失败窗口会安全移出恢复记录。未变化的记录不会反复写盘，恢复文件无法读取时也会停止后台重试并保留原文件。

恢复提示区分失败记录和其他桌面的延后记录，不再笼统归因为管理员权限。原生恢复失败会记录 HWND、进程 ID 和 Windows 返回的错误码，供诊断具体原因。

日志仅保存在本机 %LOCALAPPDATA%\StageManager\application.log，可通过“设置 → 诊断信息”查看位置和识别统计。界面操作异常会记录错误并暂停调度，不直接结束应用。

高 DPI 回归覆盖 100%、125%、150%、200% 的尺寸与边缘间距换算、负坐标屏幕、旧位置记录迁移、缩放往返和避免重复放大。当前 3840×2160、150% 屏幕已核对 WPF 实际渲染比例、主窗口 / 侧栏绘制图、侧栏展开返回的位置尺寸与弹窗 DPI；物理混合 DPI 往返仅在连接不同缩放的显示器时执行，否则明确标记 SKIP。

自动按应用归组回归覆盖同程序不同进程、独立浏览器应用身份、安全身份回退、新窗口前台 / 后台发现、指定成员启动、手动混合分组和拆分、多屏 / 虚拟桌面隔离、成员关闭及原始布局恢复。原生测试通过 Windows 窗口属性区分三个示例应用，再启动其中一个应用的新进程，确认自动加入原组且两个窗口都保持显示。焦点交接在恢复窗口尚未完成激活消息时有限重试，收到其他应用的新前台选择立即取消；预览完成检查按实际过渡状态等待，并保留明确超时上限。

恢复失败回归先复现连续 60 次扫描触发 60 次同类错误的旧行为，再验证修复后的后台不重试、明确操作可重试、成功记录不重复恢复、异常与文件损坏隔离、跨桌面继续恢复、关闭 / 隐藏后的安全清理及无变化时不写盘。真实 DWM 预览测试只对自建窗口注入恢复拒绝，检查错误提示出现后经过多轮实际计时器刷新，预览注册数量和释放次数保持不变、预览保持完整不透明度；随后通过设置按钮重试并检查记录清除。

切换回归额外覆盖组内任意成员的任务栏激活、记忆成员关闭后的回退、快速连续切换、普通及最大化窗口恢复后的实际键盘焦点和前后层级、跨屏衔接、目标恢复完成后再收起旧组，以及预览过渡前后的资源复用、减少动画设置和材质一致性。新选择取消旧交接有确定性逻辑回归；环境允许测试程序建立新的前台窗口时，还会执行一项原生取消回调检查，前提不满足则明确标记 SKIP。原生测试只管理测试进程创建的窗口；测试窗口使用独立识别路径，避免被同时运行的正式版接管。Chromium/GPU 白帧没有通过这些 WinForms 测试窗口复现，属于需要在实际应用中继续观察的边界。

环境回归覆盖原生 HWND 隐藏后退出 / 恢复仍保持隐藏、各屏独立切换及全屏避让、跨屏成员拆分、虚拟桌面分组隔离、其他桌面的延后恢复记录、重新开启调度时保留原始恢复状态和显示器合并。虚拟桌面状态转换、多显示器拔插通过虚拟窗口系统验证；原生测试核对 Windows 桌面归属接口与当前桌面识别。存在另一虚拟桌面上的窗口时，还会用自建窗口做一次跨桌面往返测试；没有该环境时明确标记 SKIP，不创建或切换用户的桌面。

```powershell
# 逻辑回归，不改变桌面窗口
.\build.ps1 -Test

# 界面回归，使用虚拟窗口状态和受控测试窗口
Start-Process .\bin\StageManager.exe -ArgumentList '--ui-test test-results\ui-test.txt' -WindowStyle Hidden -Wait

# 仅管理自行创建的三个原生测试窗口
Start-Process .\bin\StageManager.exe -ArgumentList '--integration-test test-results\integration-test.txt' -WindowStyle Hidden -Wait
Start-Process .\bin\StageManager.exe -ArgumentList '--preview-test test-results\preview-test.txt' -WindowStyle Hidden -Wait

# 实际重开窗口及桌面背景像素；运行时保持 Windows 已解锁
Start-Process .\bin\StageManager.exe -ArgumentList '--desktop-state-test test-results\desktop-state-test.txt' -WindowStyle Hidden -Wait

# 只读桌面诊断
Start-Process .\bin\StageManager.exe -ArgumentList '--diagnose test-results\desktop-diagnostics.txt' -WindowStyle Hidden -Wait

# 可交互的隔离演示，不管理你的真实应用
.\bin\StageManager.exe --demo
```

桌面诊断应在交互式 Windows 桌面运行；隔离沙箱 / 非交互会话可能只能看到自己的窗口。正式使用请直接运行 EXE，不要添加 --demo。

## 使用边界

- 仅管理当前虚拟桌面的普通应用窗口；系统工具窗口、桌面、任务栏和本应用自身被排除。
- 普通权限无法保证控制管理员或受保护窗口；读取受限的窗口仍列出并标记。
- 全屏应用默认触发避让；普通最大化窗口仍参与管理。
- 最小化、受保护内容或不支持缩略图的应用可能提供冻结预览、空白或图标。
- 侧栏不会修改 Windows 的工作区；最大化应用覆盖侧栏时使用自动收起来避让。
- 自动化测试不能代替不同硬件、混合 DPI、远程桌面及长期运行环境的持续验证。
