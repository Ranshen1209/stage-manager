# 版本记录

## 0.3.16 · 2026-09-18

- 修复切屏后最小化窗口未更新大小、位置：屏幕稳定后直接更新窗口的恢复布局，保持最小化和焦点，不再依赖选中分组；任务栏恢复、关闭前台跟随时同样生效。
- 其他虚拟桌面上的窗口在返回后适配，全屏避让中的窗口在退出全屏后适配；普通切组仍不反复提交坐标，不重新打开已关闭的应用。
- 侧栏和总览按目标工作区与 DPI 分别调整宽高，修复窄侧栏过长、总览过大。最小化和最大化总览更新其还原布局；贴边位置、手动尺寸、独立基准在重启和双向切屏后保留，避免累积缩放。
- 源码建立本地 Git 历史，继续保持闭源。公开仓库只含文档、图标、截图和编译后的下载。
- Release 打包强制执行固定版本工具的名称混淆、字符串编码及兼容模式压缩加壳，核对工具与配置哈希，再对保护后的 EXE 运行完整逻辑测试。JSON、WPF 和原生互操作所需名称保留。保护增加逆向成本，不能保证无法还原。

验证：普通构建和保护后 EXE 均通过 268 项逻辑测试，XAML 静态检查通过。按要求未运行窗口、实际切屏或远程连接测试。

## 0.3.15 · 2026-09-17

- 修复 4K / 150% 物理屏关闭后切到 1080p / 100% 虚拟屏时窗口仍然偏大。结合逻辑可用空间渐进收缩，替换“直到放不下才缩小”的策略。
- 逻辑空间明显减少时，为普通大窗口设置工作区宽、高各 80% 的软上限，保留长宽比和边缘空间。接近原空间时上限连续恢复，不因轻微分辨率变化突然跳变。
- 可读尺寸优先于软上限，保留小工具的原有尺寸；实际工作区不足时才进一步收缩。真正最大化的窗口继续保持最大化，前后层级、分组及各屏独立切换不变。
- 升级后从原布局基准重新计算旧版保存的投影结果，在虚拟屏直接启动新版也能纠正过大尺寸。标记每个成员的计算版本，避免后续重启重复覆盖目标应用已接受的大小；往返仍恢复原始基准。
- 补充低分屏起步的双向验证：1080p / 100% 上的 1000 × 700 窗口到 4K / 150% 后为 1500 × 1050，返回时恢复原尺寸与位置；在高分屏重启后仍保留低分屏基准。

验证：257 项逻辑测试、Release 构建及 XAML 静态检查通过，新增 11 项针对实际屏幕配置、双向往返、可读下限、最大化和升级兼容的回归。按要求未运行真实窗口、DPI 切换或远程连接测试，实际结果仍可能受目标应用自身尺寸限制影响。

## 0.3.14 · 2026-09-17

- 切屏尺寸策略改为优先保留按 Windows 缩放比例换算的逻辑尺寸。同一缩放比例下，窗口不会随分辨率降低而直接减半，也不会因切到大屏而无谓放大；只有目标工作区容纳不下时才等比缩小。
- 大小和位置分别计算：窗口按左右、上下剩余空间的比例放置，保留靠边和居中关系，兼容负坐标与任务栏占用。小屏优先保留可读尺寸，较大的组内窗口可以重叠，前后层级沿用原行为。
- 沿用未缩放的布局基准，避免连续往返积累误差。保留手动调整优先、分组及各屏独立、最大化 / 最小化状态、非活动组延后应用、重启保存与失败后的有限尝试，无需清空已有分组。
- 新增手动游戏模式，默认关闭，在设置页和托盘菜单切换并跨重启保存。保留窗口状态和分组，暂停自动调度、扫描、实时预览、拖放监听、中键手势和 Win+D 侧栏保护，隐藏侧栏并释放全局快捷键。
- 退出游戏模式恢复原功能设置，保留原暂停状态，重新核对已关闭窗口和显示变化；快捷键被其他程序占用时提示冲突。游戏模式下重启会延后窗口恢复和分组恢复，显式退出仍可恢复窗口。

验证：246 项逻辑测试、Release 构建和 XAML 静态检查通过。更新切屏策略回归，新增 8 项尺寸适配与 11 项游戏模式测试。按要求未运行真实窗口、游戏、DPI 切换或远程连接测试；实际结果仍可能受目标应用自身最小尺寸与显示驱动影响。
